# 对外咨询 Agent（基于 OpenAgents）总体设计（草案）

> 适用对象：客户 / 潜在客户 / 合作方  
> 场景：售前答疑、交付/支持咨询（以对外可公开资料为准）  
> 资料形态：PDF / PPT / PPTX（必要时 OCR）

## 1. 背景与目标

公司存在多个外包项目，每个项目技术背景与业务知识不同。对外咨询容易出现以下问题：

- 信息分散，回答不一致、不可追溯
- 容易“越权”泄露内部信息（客户信息、内部地址、报价、未发布路线图等）
- 资料更新后口径不统一，缺少版本管理与审计

目标：建设一个“对外资料驱动（Evidence-based）”的咨询 Agent，实现**可控权限、可追溯引用、可运营更新**的对外问答能力。

## 2. 范围与非目标

### 2.1 范围

- 将对外可共享的 PDF/PPT/PPTX 资料入库，形成可检索知识包（External Pack）
- 基于检索增强生成（RAG）进行问答，回答必须附带来源（文档名 + 页码/章节）
- 按项目/合作方进行访问控制与审计记录
- 支持“转人工/工单”闭环（不确定、无依据、敏感问题）

### 2.2 非目标（MVP 阶段不做或谨慎做）

- 直接读取内部代码仓库、内部 Wiki、内部工单系统的全量数据（除非明确授权与隔离）
- 自动回答价格/交期/合同条款/未发布路线图等承诺性内容（默认转人工）
- 取代正式对外文档/合同/技术规格书（Agent 输出不构成承诺）

## 3. 核心原则（必须落地的硬规则）

- **有依据才回答**：未检索到明确证据则拒答/转人工，不允许“推测式编造”
- **最小权限**：外部主体仅能访问其授权项目的“对外版资料”，内部资料与对外资料物理/逻辑隔离
- **可追溯**：每个回答记录命中文档版本、引用位置、检索证据、时间与用户身份
- **默认拒答敏感项**：价格/交期/路线图/内部链接/客户信息等，默认转人工
- **资料先于模型**：对外口径以“发布的对外知识包”为准，模型仅负责组织表达

## 4. 术语

- **External Pack（对外知识包）**：某项目“可对外共享”的资料集合，带版本、有效期与负责人
- **Chunk（片段）**：文档切分后的最小检索单元，附带页码/章节等引用元数据
- **RAG**：先检索证据，再基于证据生成回答

## 5. 总体架构（逻辑视图）

```text
外部用户/合作方
   │  (Web/企业IM/CRM入口)
   ▼
对外咨询服务（AuthN/AuthZ + 审计）
   │
   ▼
OpenAgents 编排/Agent
   │        │
   │        ├─ 工具：search_docs(project, query, audience)
   │        └─ 工具：create_ticket(...)
   ▼
检索层（权限过滤 + 混合检索）
   │
   ├─ 全文索引（关键词/精确匹配）
   └─ 向量库（语义检索）
   ▼
知识库数据层
   ├─ 对象存储：原始文件/规范化PDF
   ├─ 元数据DB：文档版本、权限、页码映射、发布状态
   └─ chunks：文本片段 + 元数据
```

## 6. 文档入库（数据流水线）设计

### 6.1 入库输入与输出

#### 输入
- PDF（文本型、扫描型、混合型）
- PPT/PPTX（建议保留“备注/讲稿”）

#### 输出（入库产物）
- 原始文件归档（只读）：用于追溯与复核
- 规范化副本（推荐统一 PDF）：用于稳定页码引用
- 结构化抽取结果：按页/块/表格的文本
- Chunk 片段库：用于检索的最小单元
- 元数据与权限标签：项目、版本、对外范围、页码等
- 入库质量报告：抽取/OCR 覆盖率、异常页、处理日志

### 6.2 处理步骤（推荐顺序）

1. **采集与登记**
   - 录入：`project_id`、`doc_title`、`doc_version`、`published_at`、`owner`、`visibility`、`expires_at`
   - 计算 `source_hash`（用于去重与追溯）
2. **格式识别与分流**
   - 判断 PDF 是否文本可抽取、是否需要逐页 OCR
   - PPT/PPTX：优先抽“文本框 + 备注/讲稿”，并导出规范化 PDF
3. **抽取与 OCR（可插拔）**
   - 文本型 PDF：抽取文字与块信息（尽量保留页码与标题结构）
   - 扫描/图片页：OCR（必要时预处理：纠偏、二值化、去噪）
   - 表格：优先结构化抽取；不行则转“行文本”
4. **清洗与归一化**
   - 去除页眉页脚重复、合并断行、规范化空白/全角半角
   - 异常检测：乱码率、空白页、极短页
5. **结构化（标题/章节路径）**
   - 从文档结构或版式推断 `section_path`（如：产品A > 部署 > 网络要求）
   - 对 PPTX 可直接使用“页标题”作为一级路径
6. **切分（Chunking）**
   - 结构优先：按段落/项目符号切分
   - 长度兜底：按字数切分（建议 300–800 中文字/片段，重叠 50–100 字）
   - 每个 chunk 必须携带：`page_start/page_end`、`section_path`、`doc_version`
7. **元数据与权限绑定**
   - `project_id` 强制字段（对外检索必须过滤）
   - `audience`（客户/潜客/合作方）与可选 `partner_allowlist`
   - `published_state`：`draft` / `published` / `deprecated`
8. **质量检查与入库报告**
   - 抽取字符总量、每页字符数分布、OCR 覆盖率
   - 抽样人工核验：每 20 页抽 2 页对照原文
   - 未达标：回退为 `draft`，禁止对外检索
9. **写入索引**
   - 全文索引：用于关键词/短语/术语精确命中
   - 向量索引：对 chunk 计算 embedding 写入向量库

### 6.3 质量门槛（建议的“可发布”条件）

- 必填元数据齐全：项目、版本、发布日期、对外范围、负责人
- 抽取成功率达到阈值（例如：文本型 PDF ≥ 95% 页面有有效文本；扫描件 OCR 覆盖明确）
- 关键页无明显乱码/空白（通过抽样人工核验确认）

## 7. 存储与索引（数据模型概要）

### 7.1 数据分层

- **对象存储（Files）**：原始文件、规范化 PDF、（可选）OCR 中间图像
- **元数据 DB（Metadata）**：文档版本、发布状态、权限、页码映射、负责人、有效期
- **Chunk 存储（Chunks）**：文本片段 + 元数据（可与元数据 DB 同库）
- **索引（Search）**
  - 全文索引（倒排）
  - 向量索引（embedding）

### 7.2 Chunk 最小字段（示例）

- `chunk_id`
- `project_id`
- `doc_id`、`doc_title`、`doc_version`
- `published_at`、`expires_at`、`published_state`
- `visibility`、`audience`、`partner_allowlist`（可选）
- `page_start`、`page_end`
- `section_path`
- `text`
- `source_hash`

## 8. 检索与回答（对外问答流程）

### 8.1 请求流程

1. 外部用户登录/鉴权（映射 `partner_id` + 可访问 `project_id` 列表）
2. Agent 接收问题 → 识别意图（售前/支持/敏感项）与目标项目（必要时追问澄清）
3. 调用 `search_docs`：
   - 先做权限过滤（project + audience + allowlist）
   - 再做混合检索（全文 + 向量），返回 TopK chunk（含引用元数据）
4. 生成回答：
   - 仅基于检索证据组织语言
   - 输出“引用列表”（文档名 + 版本 + 页码/章节）
5. 无证据/敏感/不确定 → 调用 `create_ticket` 或引导人工对接

### 8.2 建议的对外输出格式

- **结论**：1–3 句直接回答
- **依据**：列出引用（文档名、版本、页码/章节）
- **边界/注意**：若存在适用条件、不支持项，明确说明
- **下一步**：需要更多信息时，列出需要用户补充的参数（环境、版本、部署方式等）

## 9. OpenAgents 集成方式（建议）

> OpenAgents 负责“Agent 协作/编排”，检索与入库作为其工具/服务接入。

### 9.1 工具接口（建议最小集）

- `search_docs(project_id, partner_id, audience, query, top_k) -> chunks[]`
  - 返回字段：`text`, `doc_title`, `doc_version`, `page_start`, `page_end`, `section_path`, `score`
- `create_ticket(project_id, partner_id, question, context, contact) -> ticket_id`

### 9.2 Agent 行为约束（建议）

- 未调用 `search_docs` 不允许直接回答专业问题
- 引用不足（无文档名/页码）视为不合规输出
- 敏感项检测命中（价格/交期/路线图/内部链接/客户信息）→ 强制转人工

## 10. 权限、审计与合规

### 10.1 权限模型（MVP）

- 外部主体（partner）→ 授权项目列表（project allowlist）
- External Pack 仅包含对外资料；内部资料禁止入对外索引

### 10.2 审计记录（必须）

- `who`：用户/合作方标识
- `when`：时间
- `what`：问题、回答
- `evidence`：命中文档版本、引用页码、chunk_id 列表、检索 query
- `action`：是否转人工/工单号

### 10.3 脱敏与发布流程

- 原始资料 → 脱敏审查 → 生成 External Pack → 发布（可检索）
- 发现泄露风险 → 立即下线对应 doc_version（`deprecated`）并回滚

## 11. MVP 里程碑（建议）

- M1：单项目 External Pack 入库 + 混合检索 + 引用输出
- M2：权限接入（按合作方授权项目）+ 审计日志 + 转人工/工单
- M3：OCR 兜底、质量报告与发布门槛、资料到期提醒

## 12. 附录：入库检查清单（简版）

- 文档是否“对外可共享”并完成脱敏审查
- 元数据是否齐全（项目、版本、发布日期、负责人、有效期、对外范围）
- 抽取文本是否可读（无明显乱码/空白）
- 引用是否可定位（页码正确、标题路径合理）
- 发布后抽样问答是否能稳定命中并给出正确引用
