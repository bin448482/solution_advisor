# Vector Database Module (src/vectordb/)

Provides Chroma vector database integration for RAG document storage and retrieval.

## Overview

This module wraps ChromaDB to provide persistent vector storage for RAG documents generated by the PPT parsing pipeline. It supports document insertion, semantic search, metadata filtering, and collection management.

## Key Components

### ChromaStore (chroma_store.py)

Main class for Chroma vector database operations.

**Features**:
- Persistent local storage
- Automatic collection creation
- Batch document insertion with progress tracking
- Semantic search with metadata filtering
- Project-level document management
- Idempotent operations (upsert-based)

**Collection Schema**:
```python
{
    "id": "ChatBI_slide_001",           # Unique document ID
    "embedding": [0.1, 0.2, ...],       # 768-dim vector (m3e-base)
    "document": "项目: ChatBI\n...",     # Semantic text for display
    "metadata": {
        "project_name": "ChatBI",
        "source": "ChatBI",
        "slide_no": 1,
        "page_type": "[\"positioning\"]",  # JSON string
        "entities": "[\"ChatBI\", \"BI\"]", # JSON string
        "confidence": 0.9,
        "level": "slide",                # "slide" or "project"
        "original_json": "{...}",        # Full PageSummary JSON
        "indexed_at": "2025-12-30T08:00:00Z"
    }
}
```

**Distance Metric**: Cosine similarity (hnsw:space = "cosine")

## Usage

### Basic Initialization

```python
from src.embeddings import M3EEmbedding
from src.vectordb import ChromaStore

# Initialize embedding model
embedding_model = M3EEmbedding(
    model_name="moka-ai/m3e-base",
    device="cpu",
    cache_dir="./models"
)

# Initialize vector store
store = ChromaStore(
    persist_dir="./chroma_db",
    collection_name="project_slides",
    embedding_model=embedding_model
)
```

### Inserting Documents

```python
# Load RAG documents from pipeline output
import json
with open("ppt_outputs/ChatBI/embeddings/rag_documents.json") as f:
    rag_docs = json.load(f)

# Insert documents (idempotent - can run multiple times)
success, failure, errors = store.insert_documents(
    rag_docs,
    batch_size=100
)

print(f"Inserted: {success}, Failed: {failure}")
if errors:
    print(f"Errors: {errors}")
```

### Querying Documents

```python
# Basic semantic search
results = store.query(
    query_text="ChatBI的核心功能是什么",
    n_results=5
)

for result in results:
    print(f"ID: {result['id']}")
    print(f"Distance: {result['distance']}")
    print(f"Text: {result['document'][:100]}...")
    print(f"Metadata: {result['metadata']}")
    print("---")
```

### Metadata Filtering

```python
# Filter by project
results = store.query(
    query_text="架构设计",
    n_results=5,
    where={"project_name": "ChatBI"}
)

# Filter by confidence
results = store.query(
    query_text="技术栈",
    n_results=5,
    where={"confidence": {"$gt": 0.8}}
)

# Filter by level (slide vs project)
results = store.query(
    query_text="产品定位",
    n_results=3,
    where={"level": "project"}
)
```

### Project Management

```python
# List all projects
projects = store.list_projects()
print(f"Projects: {projects}")

# Get collection statistics
stats = store.get_collection_stats()
print(f"Total documents: {stats['total_documents']}")
print(f"Unique projects: {stats['unique_projects']}")

# Delete a project
deleted_count = store.delete_by_project("ChatBI")
print(f"Deleted {deleted_count} documents")
```

## Metadata Handling

### List Fields

Chroma doesn't natively support list metadata, so lists are stored as JSON strings. 插入前会对所有 list 类型字段统一序列化（包括 `page_type` / `entities` / `source_slide_refs` 等）：

```python
# Original metadata
metadata = {
    "page_type": ["positioning", "features"],
    "entities": ["ChatBI", "BI", "数据分析"]
}

# Stored in Chroma as
metadata = {
    "page_type": "[\"positioning\", \"features\"]",
    "entities": "[\"ChatBI\", \"BI\", \"数据分析\"]"
}

# To use in queries, parse back
import json
page_types = json.loads(result["metadata"]["page_type"])
```

### Filtering with JSON Strings

For list fields, use string matching:

```python
# Check if page_type contains "architecture"
results = store.query(
    query_text="系统架构",
    where={"page_type": {"$contains": "architecture"}}
)
```

## Error Handling

### Embedding Generation Failures

If embedding generation fails for the entire batch:
- Returns (0, total_count, [error_dict])
- Error includes full exception message
- No documents are inserted

### Batch Insertion Failures

If a batch fails during insertion:
- Continues with remaining batches
- Collects errors with batch_start and batch_size
- Returns partial success count

### Duplicate IDs

Documents with duplicate IDs are handled via upsert:
- Existing documents are updated (not duplicated)
- Idempotent: safe to run multiple times
- No errors raised for duplicates

## Performance Considerations

### Batch Size

**Embedding Generation**:
- Controlled by embedding_model.embed_texts()
- Automatically adjusted based on model dimension
- Default: dimension // 8 (e.g., 96 for 768-dim)

**Document Insertion**:
- Default: 100 documents per batch
- Larger batches: faster but more memory
- Smaller batches: slower but safer

### Index Quality

Collection metadata controls HNSW index quality:
- `hnsw:construction_ef: 200` - Build quality (higher = better, slower)
- `hnsw:search_ef: 100` - Search quality (higher = better, slower)

Adjust these for speed vs accuracy tradeoff.

### Persistence

- All data persisted to disk automatically
- No explicit save/commit needed
- Safe to restart application

## Common Issues

### "Collection not found"

Solution: Collection is auto-created on first access. If error persists, check persist_dir permissions.

### "Embedding dimension mismatch"

Solution: Ensure all documents use same embedding model. Delete collection and re-insert if model changed.

### "Out of memory during insertion"

Solution: Reduce batch_size parameter in insert_documents().

### "Slow query performance"

Solution: Increase hnsw:search_ef in collection metadata (requires recreating collection).
